# 必要条件・十分条件探索：独立機能の仕様

## 位置付けと実装状態

「順位確率」と「条件探索」を別の機能・画面・実行単位にする。条件探索はv0.4.0で実装済み。既存の確率計算結果を後から加工する機能ではなく、共通の試合生成・順位比較に条件探索専用の存在集計を接続する。

| 項目 | 順位確率 | 条件探索 |
| --- | --- | --- |
| 目的 | 各順位・PO進出の確率 | 何点・何勝が必要か、何点・何勝なら保証できるか |
| 計算方式 | 厳密全探索／モンテカルロ | 厳密探索のみ |
| 主な集計 | 順位ごとの確率 | 対象チームの成績と達成判定の対応 |
| 未解決同点 | 均等配分または上下限（順位判定に依存） | 均等配分禁止。保守的に保証可能性を判定 |
| 出力 | 確率表・比較 | 必要条件・十分条件・境界の具体例と反例 |

## 共通化する処理

- 大会・ディビジョン・チーム・現在値・残り日程と実結果の更新。
- 整合したチームマッチのポイント・バトル差・ラウンド差の生成。
- 順位決定規則、未解決同点の判定。
- 明示的に仮定を使う場合の試合別固定とシナリオ優先順位・スキップ規則。
- 厳密な状態表現、入力検証、Worker実行と中止。

データや規則を別実装へ複製して乖離させない。一方、集計値・高速化の終了条件・結果形式は目的別に分ける。

## 入力と画面

条件探索の入口で以下を指定する。

1. ディビジョンと対象チーム。
2. 目標A：PO進出（3位以内）／1位通過（本節1位）。プレイオフ自体の勝敗ではない。
3. 順位判定：ラウンドまでを標準とし、ポイントのみ・バトルまでの保守的探索も選べる。
4. 探索の前提：通常状態（将来の仮定なし）／指定したシナリオケース下。

初期範囲では、対象チームについてポイントと勝利数の単独しきい値を両方求める。「N点以上かつM勝以上」等の組み合わせ条件・複数候補の境界探索は将来の拡張とする。

必要な現在のバトル差・ラウンド差が不明なら、その順位判定での探索を開始できない。不明を0に置換したり、過去の結果を抽選して補完したりしない。既存の累計値補完機能を共用する。

通常状態では実結果だけを現在値へ反映し、確率画面の仮定スコア・シナリオは適用しない。「通常状態（仮定なし）」を、共通の固定スコアが適用される確率比較の「基準ケース」と混同しない。

シナリオケースを選んだ場合は、そのケースのチーム条件と共通固定スコアを適用し、スキップを解決した後の有効条件を前提とする。結果に「指定シナリオ下の条件」と明示し、適用内容を保存する。対象チームの全勝等が前提なら、その制約から生じる自明な条件も無条件の発見として表示しない。

## Bの定義

- ポイント条件：対象チームが残りのチームマッチで合計N点以上を獲得する。
- 勝利数条件：対象チームが残りのチームマッチでM勝以上する。
- 現在までのポイント・勝利数は含めない。ポイントは現在値を足した最終到達値を併記する。
- 勝利数はチームマッチの勝利を数える。先鋒・中堅・大将・延長の勝利数や、バトル勝利数とは異なる。30–20も1勝。
- 「ちょうどN点」「ちょうどM勝」とは扱わない。候補しきい値はポイントでは0から10点刻み、勝利数では0から1勝刻み。

「X点なら進出」と単一スコアだけを調べず、X以上を獲得する全パターンを調べる。勝利数も同様。

## 達成判定

各終状態で、対象チームより厳密に上位のチーム数をh、対象チームを含む未解決同点のチーム数をkとする。目標順位の上限をCとし、POはC=3、1位通過はC=1。

- 達成確定：h+k≤C。
- 非達成確定：h+1>C。
- 未確定：上記以外。同点内の順位によって達成・非達成が変わる。

ポイントのみではポイント同点、バトルまでではポイント・バトル差同点に未探索項目による不確定性が残る。ラウンドまで探索すると未探索の順位決定項目はなくなる。3項目完全一致だけは、次項の追加タイブレーク戦の結果が未確定となる。既存ポイント確率モードの同点均等配分を流用しない。

これにより、目標の境界に関係しない同点は達成確定／非達成確定に分類できる。例えばPOで1〜2位の同点は進出確定。3〜4位の同点は未確定。

### 3項目完全一致と追加タイブレーク戦

公式競技細則を確認したユーザーの報告に基づき、ポイント・バトル差・ラウンド差が完全一致した場合は追加タイブレーク戦で同点内の順位を決めることを確定ルールとして扱う。参照の記録は[rules-source.md](rules-source.md)を参照。追加戦自体の勝敗・方式・勝率はモデル化せず、同点内の対象順位を得る可能性は残すが、勝利を保証しない。

目標の境界で完全一致となる終状態は、達成可能性があるため必要条件の探索対象Pに含める。一方、追加戦で敗れる可能性があるため、十分条件の判定では保証できない集合Qにも含める。「完全一致以上なら可能性が残るが、境界での完全一致だけでは保証にならない」と解釈する。

対象チームを除く5チームを3項目の辞書式で並べ、そのC番目のチームを境界の比較対象とする。このとき、ある終状態における到達可能性と保証を次で表せる。

- 対象チームの3項目が境界の比較対象以上（完全一致を含む）：達成の可能性が残るために必要。
- 対象チームの3項目が境界の比較対象を厳密に上回る：追加戦の勝敗によらず達成を保証する。
- 境界の比較対象と完全一致：可能性はあるが、その終状態だけでは達成を保証しない。

これは終状態の順位関係の定義であり、N点以上・M勝以上という単独成績の条件とは区別する。単独成績の十分条件は、そのしきい値以上の全終状態で保証が成立することを要求する。

同点グループ全体が目標順位以内なら、完全一致でも目標の達成は確定する。例えば1〜3位が完全一致の3チームなら全員PO進出は確定だが、1位通過は追加戦次第。3〜4位の完全一致ならPO進出は追加戦次第。従来のh・k・Cによる3分類はこの解釈でも維持する。

表示では「未探索項目による同点」と「全項目一致・追加タイブレーク戦次第」を区別する。ポイント・バトルだけでも保証できる条件はあるが、最も緩い条件を求め切ったとは限らない。

## 必要条件・十分条件

実現可能な終状態のうち、「達成確定または未確定」の集合をP、「非達成確定または未確定」の集合をQとする。PとQは未確定の終状態で重なる。

### 必要条件

Pの全要素に共通する最低成績を求める。

- 必要最低ポイント：Pの残り獲得ポイントの最小値。
- 必要最低勝利数：Pの残り勝利数の最小値。

これを下回る成績では達成できない。一方、その値に到達しても達成するとは限らない。未確定をPへ含めるため、実際の公式処理が判明した場合の最も強い必要条件より弱い可能性がある。

### 十分条件

しきい値以上を獲得する実現可能パターンが1つ以上存在し、そのすべてが達成確定となる最小のしきい値を求める。

- Qが空でなければ、その最大ポイントを超える最初の10点刻みを候補とする。
- 勝利数もQの最大勝利数を超える次の整数を候補とする。
- 候補以上を達成する実現可能パターンがなければ、その指標の十分条件は存在しない。

未確定をQへ含めるため、安全側の十分条件となる。達成不可能な成績を、論理上の空虚な十分条件として表示しない。

しきい値そのものの成績が実現可能である必要はなく、「しきい値以上」の実現可能な集合が非空であることを要求する。前提によって中間の成績が実現しない場合、必要値の数値より低い十分しきい値が、同じ実現可能集合を指すこともある。数値の大小だけで矛盾とせず、境界例と反例で確認できるようにする。

例えばPの最小ポイントが50、Qの最大ポイントが70で、80点以上が実現可能なら「少なくとも50点が必要」「80点以上なら保証できる」となる。これは説明用の例で、現在の大会データを計算した結果ではない。

## 特殊な結果の表示

- 全終状態が達成確定：現在の前提で達成確定。追加0点・0勝でも保証できることを表示する。全勝等のシナリオ付きなら、その前提による確定であると併記する。
- Pが空：現在の前提では達成不可能。必要しきい値を無限大等として表示せず、十分条件も出さない。
- Pは空でないが達成確定が存在しない：達成できる可能性はあるが、未解決同点等により保証できるパターンがない。
- ある指標でQの最大値が実現可能な最大値まで達する：その指標だけでは保証できるしきい値なし。もう一方の指標の結果と区別する。
- 必要値が0：この指標による正の最低条件は得られない。「0点なら進出」と誤読させない。
- 全探索未完了：最終的な必要条件・十分条件として表示しない。途中で反例が見つかった事実を表示する場合も未完了と明示する。

## 保証の意味と表示

選択したモデルが生成する実現可能パターンと、指定した前提の範囲内で保証する。表示時に確率が0%へ丸められたパターンも、厳密な重みが正なら除外しない。

ラウンドまでの結果で境界に完全一致が残る場合は「全項目一致・追加タイブレーク戦次第」と表示する。ポイント・バトルだけの場合は「未探索の得失点差による不確定性」を明示する。どちらも必要・十分条件を安全側に判定し、最も強い必要条件・最も緩い十分条件を公式規則上完全に確定したと称さない。

必要条件・十分条件の要約に加え、未解決同点がどの成績の境界に影響するか確認できるようにする。反例や境界の具体例の対戦表から、ポイント・得失点差・勝利数の整合性を追跡できるようにする。

## 集計方法

対象チームについて、少なくとも次の対応を保持する。

`残り獲得ポイント × 残り勝利数 → 達成確定／非達成確定／未確定の存在`

終状態の判定には、選択した順位判定に必要な全チームの現在値＋将来増分を使用する。対象チームだけの成績から順位を独立に抽選しない。

各分類の存在判定を必須とし、代表例を保持する。確率重みの集計は付加情報として保持してよいが、必要・十分条件の論理判定に確率の大小や表示桁数を使わない。既存の順位確率だけの周辺集計からこの対応を復元できるとは扱わない。

全履歴の保存は不要。各成績・判定セルに代表例を1つ保持する等で、完全な反例を復元できるようにする。バトル・ラウンド差を持つ結果例は、その差が実現するプレイヤーマッチ・バトル・ラウンドのスコア例まで再構成できる情報を持たせる。順列そのものの表示は必須ではない。

## 高速化の条件

確率計算の「残りの結果によらず順位が同じなら一括集計」を、そのまま条件探索へ流用しない。順位が変わらなくても、対象チームの最終ポイント・勝利数は変わるためである。

部分木を省略・統合できるのは、達成分類に加え、対象チームの残り獲得ポイント・勝利数の実現可能性と代表例を正確に保存できる場合だけとする。例えば順位の分類が固定なら、残り試合のポイント・勝利数の同時分布を厳密に畳み込む方法は認める。できなければ探索を続ける。

勝利数は順位決定には使わないが、この分析の状態・終状態集計では必要。ラウンドまでの探索で、ラウンド差の異なる状態を消して統合しない。条件探索専用の証明可能な枝刈りを認めるが、未観測・未探索を非実現可能とみなさない。

## 反例・境界例

- 必要条件の最低値で達成確定または達成可能となる代表例。
- 十分条件より10点少ない、または1勝少ない成績で、保証できないことを示す代表例。ちょうどその成績のパターンがなければ、Qの最大成績の代表例を示す。
- 未確定の例は敗退確定の反例と呼ばず、「未解決同点が残り保証できない例」と表示する。
- 必要条件を満たすが達成できない例があれば、必要条件だけでは十分でないことの説明に使える。

すべての代表例に、適用シナリオ、実現する最終集計値、対象チームの成績、分類を添える。

## 実行・保存

厳密探索のみとし、モンテカルロから確定条件を宣言しない。計算量の参考表示と大規模時の警告は[組合せ数仕様](exhaustive-cost.md)を共用するが、条件探索の計算量・所要時間が順位確率と同じとは保証しない。

処理時間に上限を設けず、Workerで実行する。警告による実行禁止や追加確認はしない。中止できるようにし、中止した結果から最終保証を出さない。モンテカルロへの自動切替は禁止。「順位確率」へ移って近似確率を調べる操作を設けても、条件探索の近似版とは扱わない。

入力スナップショット、対象チーム、目標、順位判定、モデルバージョン、適用条件・スキップ、集計表、必要・十分条件、代表例、完了状態を結果JSONへ保存する。確率計算の結果JSONとは種類を区別する。入力変更後は古い結果と表示する。途中保存・再開は今回の追加範囲では保証しない。

## 検証項目

- 小規模な独立全列挙と、成績別3分類・しきい値・代表例が一致する。
- 必要値を下回る全パターンに達成可能なものがない。
- 十分値以上の実現可能パターンが非空で、すべて達成確定。
- 必要値の境界例と、十分条件をこれ以上緩められないことの反例または非実現可能性を確認する。
- 同点を均等配分せず、未確定をPとQの双方へ含める。
- 目標境界と関係しない同点、POの3〜4位同点、1位の同点、3項目一致を正しく区別する。
- 完全一致が目標境界をまたぐ終状態をPとQの両方へ含め、追加戦の勝者を無条件に抽選・確定しない。グループ全体が目標以内なら達成確定とする。
- ラウンドまでの終状態で、他5チームのC番目との辞書式比較と、h・kによる判定が一致する。
- 残り0試合、既に確定、達成不可能、十分条件なし、必要値0を正しく表示する。
- 30–20勝利を1勝として数え、延長の得失点差も反映する。
- 稀でも実現可能な反例を除外しない。
- 条件付き探索の保証を、通常状態の保証と取り違えない。
- 順位固定の部分木でもポイント・勝利数の範囲を失わず、最適化の有無で結果が一致する。
- 代表例を再集計すると、表示した成績・得失点差・達成分類を再現できる。
- 中止した計算やモンテカルロ結果から、確定条件を表示しない。
