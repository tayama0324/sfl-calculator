# SFL 2026 順位確率計算ツール：初版仕様

追加機能は[シナリオ比較の仕様](scenario-comparison.md)および[バトル・ラウンド全探索モードの仕様](exhaustive-modes.md)を参照。この文書は初版の仕様を記載しており、現在実装済みの追加機能で変更した点は別紙に明記する。

## 目的と範囲

全項目完全一致の扱いは、[条件探索仕様](condition-search.md)および[詳細モード仕様](exhaustive-modes.md)の追記に従う。ユーザーが公式競技細則を確認した報告に基づき、追加タイブレーク戦で同点内の順位を決めることを確定ルールとする（[出典記録](rules-source.md)）。境界での完全一致は達成可能性に含めるが保証には含めず、追加戦の勝敗はモデル化しない。判定式は従来の保守的な上下限を維持し、理由の表示を区別する追加仕様とする。

必要条件・十分条件の探索は、[条件探索の仕様](condition-search.md)に従い、「順位確率」と独立した画面・実行・集計機能として追加した。データ・試合モデル・順位比較・シナリオ解決は共用する。v0.4.0で実装済み。

実行前の計算量表示と警告の追加仕様は[厳密全探索の組合せ数・警告](exhaustive-cost.md)を参照。条件を無視した集約状態の組合せ数を参考値として表示する。v0.4.0で実装済み。

モンテカルロの合意済み追加仕様は[モンテカルロ仕様](monte-carlo.md)を参照。計算方式と順位判定を独立して選択する。以下の初版記述にある自動切替禁止は維持し、ユーザーが明示的に近似計算を選べる。モンテカルロはv0.3.0で実装済み。

GitHub Pages 上で動作する静的ページ。Division S / F を独立に計算し、本節終了時の順位と上位3チームのプレイオフ（PO）進出確率を表示する。初版はポイントのみを比較し、同点は占有順位へ均等配分する。公式タイブレークを反映しないモデル上の確率であることを常時明示する。

モンテカルロへ自動変更せず、全可能性を厳密に重み付き集計する。処理時間に上限は設けない。バトル差・ラウンド差による順位計算、プレイオフとグランドファイナルの勝敗計算は初版対象外。

## 画面構成

1. ヘッダー：タイトル、非公式ツールの表示、モデルの説明、データ基準日。
2. ディビジョン切替：S / F。各ディビジョンの入力・計算結果は独立。
3. 現在の状態：チーム名、消化数、ポイント、バトル差、ラウンド差。基準値の編集機能を設ける。初版の比較対象はポイントのみ。
4. 残り日程：節、ホーム、アウェイ、実結果の登録、仮定スコア。実結果と仮定は操作・表示を分離。
5. 条件設定：通常、対象1チームの全勝・全敗・全40–0・全0–40、および任意試合のスコア固定。
6. 実行領域：入力検証、計算開始、経過時間、処理済み数、中止。正確な総数を算出できる方式でのみ進捗率を表示。
7. 結果：チームごとの1〜6位確率、PO進出確率、適用条件、計算対象データの識別情報。正の微小確率は科学的記数法、厳密なゼロは0%。
8. データ管理：ブラウザ保存、JSON読み込み・書き出し、初期データへ戻す操作。

入力変更後は結果を「変更前の入力による結果」と表示する。計算開始時の入力を固定し、結果と対応付ける。中止した部分集計を完成した順位確率として表示しない。

## データ形式

JSONにschemaVersionを持たせる。名前とは別の安定したIDでチーム・試合を参照する。

| 区分 | 主な項目 |
| --- | --- |
| 大会 | id, season, title, sourceUrl |
| ディビジョン | id, teamIds, qualificationPlaces（3） |
| チーム | id, name, shortName |
| 日程 | id, divisionId, round, homeTeamId, awayTeamId, scheduledAt |
| 基準状態 | asOf, sourceStatus, includedMatchIds, standings |
| チーム基準値 | teamId, played, points, battleDiff, roundDiff |
| 基準後の確定結果 | matchId, homePoints, awayPoints, homeBattleDiffDelta, homeRoundDiffDelta |
| 仮定条件 | targetTeamId, mode, fixedScores |

得失点差の増分はホーム側だけを保存し、アウェイ側は符号を反転して導出する。未入力はnullとし、0と区別する。基準値が既知でも、追加結果の差分が未入力なら現在の差は不明として表示する。

includedMatchIdsは基準集計に含まれる試合を示す。その試合を追加結果として再登録できないようにする。全日程取得前はデータをdraft扱いとし、完全性検証前の計算を無効にする。

現在値は基準状態と基準後の確定結果から毎回再計算する。結果の訂正・取消時も再計算し、差分の重複適用を避ける。基準前の試合の個別編集は初版対象外とし、基準状態を編集または置換する。任意の基準変更も整合性検証する。

## ポイント確率モデル

ホーム対アウェイの結果と重みは次のとおり。各試合を双方別々には生成しない。

| スコア | 重み / 8 |
| --- | ---: |
| 40–0 | 1 |
| 30–10 | 2 |
| 30–20 | 1 |
| 20–30 | 1 |
| 10–30 | 2 |
| 0–40 | 1 |

各試合の候補を条件で絞り、残った重みで正規化する。全勝条件は対象チームの参加試合だけに適用し、勝ち側スコアの確率は1/4、1/2、1/4。全敗も対応する負け側スコアで同様。特定スコアの固定は確率1とする。対象外の試合は通常分布のまま。

全勝等と試合固定の併用は両条件の共通部分を使用する。候補が0になる場合は矛盾エラーとする。条件自体の実現確率は結果へ掛けない。全40–0はバトル差を指定する条件ではない。

## 厳密集計と精度

ポイントは10pt単位の整数で扱える。候補の整数重みと分母を使い、途中で確率を丸めない。BigInt等で整数を保持する。最終同点の均等配分も有理数として扱い、6チームの同点人数1〜6の最小公倍数60を利用して整数累積できる。例えば経路重みWのkチーム同点では、各占有順位にW×60/kを加算する。共通分母は全経路重みの合計×60。

列挙または同一状態の統合で全結果を集計する。方式の採用は計算エンジン試作で判断する。全状態をメモリに保持する方式だけに依存せず、省メモリ列挙も候補とする。計算はWeb Workerで行う。

初版のポイント計算はバトル差・ラウンド差を読み取って順位を決めてはならない。

## 入力検証

- IDの一意性、参照先の存在、同一チーム同士の対戦禁止。
- 各ディビジョン6チーム、全30試合、各チーム10試合、各組合せ2試合、ホーム・アウェイ各1回。各節3試合で各チーム1試合。
- 基準に含まれる試合数とplayedの一致。確定・未消化・基準内の区分が重複しない。
- ポイントは非負の10の倍数。1試合の最終スコアは6種類のみ。
- 全差分が既知ならディビジョンのバトル差・ラウンド差の合計は各0。
- 基準ポイント合計は40×基準試合数＋10×延長試合数に整合すること。延長試合数は0〜基準試合数の整数。
- 仮定は未消化試合だけに指定。条件矛盾を計算前に検出。
- JSONは読み込み時に検証し、成功するまで保存済みデータを置き換えない。

## 検算・受け入れ条件

- 各チームの順位確率合計が厳密に1。
- 各順位の6チーム確率合計が厳密に1。
- PO進出確率合計が厳密に3。
- 未消化0試合のとき最終ポイントに基づく確定順位／同点配分を返す。
- 全6チーム同点のとき全チーム各順位1/6、PO1/2。
- 1試合の分布・全勝条件・ホーム／アウェイ反転が定義と一致。
- 全固定では確率分岐がなく、最終順位または同点配分のみを返す。
- 条件固定と実結果登録を混同しない。訂正・取消で現在値が正しく復元される。
- 微小な正の確率を0%として表示しない。

## 保存と公開

標準データはバージョン付きJSONとしてコードから分離する。ブラウザ保存は端末・ブラウザ単位。公開ページの更新と閲覧者の手元の編集は独立。ブラウザ保存の失敗時は画面で知らせ、JSON書き出しで保存できる。

GitHub Pagesのプロジェクト配下のURLでも動作する相対パスを使用する。計算実行時の外部API・ログイン・サーバーは不要。日程のライブ取得は初版の前提にしない。

## 実装状況

ポイント簡易モード、Workerによる厳密列挙、条件指定、結果更新、保存、GitHub Pages公開用のワークフローを実装済み。日程・集計の整合性、小規模な独立列挙との照合、保存則などを自動テストする。公開手順はREADME参照。

シナリオ比較、バトル・ラウンドまでの厳密全探索、未確定順位の上下限、モンテカルロを追加実装済み。設定JSONはschemaVersion 3となり、schemaVersion 1・2を自動移行する。公式日程との直接照合は引き続き未完了。
