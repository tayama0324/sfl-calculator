# シナリオ比較：合意済み仕様

## 状態と目的

[条件探索](condition-search.md)でも同じ優先順位・スキップ処理を共用する。ただし条件探索の通常状態は将来の仮定なしを標準とし、共通固定が適用される本機能の基準ケースと区別する。ケースを指定した条件探索の保証は、その解決済みの前提下だけのものとして表示する。

2026-11-07の会話で合意した追加機能の仕様。比較機能は実装済み。ポイントモードでは厳密集計と同点均等配分を引き継ぐ。[バトル・ラウンド全探索モード](exhaustive-modes.md)でも同じ条件の優先規則を使うが、未解決同点は均等配分せず確率の上下限で表示する。

## 用語と入力

- シナリオ条件：対象1チームと達成条件の組。画面の表記は「残り全試合でチームAがB」。
- Bの選択肢：40–0で勝利する／勝利する／敗北する／0–40で敗北する。
- 比較ケース：名前と、優先順位を持つシナリオ条件のリスト。
- 基準ケース：チームに対するシナリオ条件を持たない比較対象。

比較は同一ディビジョン・同一の現在状態・同一の残り日程に対して行う。現在の試合別固定スコアは全比較ケースと基準ケースで共通にする。基準ケースは固定スコアを解除した通常モデルとは限らないことを明示する。

各ケースで条件の追加・編集・削除・並べ替えができる。同じチームの複数指定を許可する。並べ替えは入力の変更として結果を古いものと表示する。

探索モードも全ケースと基準で統一する。詳細モードでは、試合ごとの許容ポイントスコアを以下の手順で解決した後、その条件下のバトル・ラウンドの詳細分布を元の重みで集計する。

## 適用優先順位

1. 実結果は現在状態へ反映し、その試合を未消化日程から外す。
2. 未消化試合ごとの固定スコアを適用する。
3. 各ケースのシナリオ条件を先頭から順に適用する。

後の条件は先頭だけでなく、それ以前に適用済みのすべての条件に従う。優先順位はケースごとに独立する。別ケースの条件は影響しない。

## 試合ごとの条件解決

未消化の各試合について、以下を独立に実行する。

1. 基本モデルの6スコアと元の整数重みを候補にする。
2. 固定スコアがあれば、そのスコアだけに絞る。
3. シナリオ条件を順に確認する。対象チームが参加しない試合には適用しない。
4. 現在の候補と、その条件を満たすスコアの共通部分を求める。
5. 共通部分が空でなければ、候補をその共通部分に置き換える。
6. 空なら、その試合におけるその条件だけをスキップし、現在の候補を保持する。先に適用した条件を解除しない。同じ条件はほかの対象試合では引き続き判定する。
7. すべての条件を処理後、残った候補を元の重みで正規化する。

空になった場合、候補の一部を残すために先の条件を緩和したり、後の条件を別の意味へ変更したりしない。候補が減らない場合でも、両立する条件として扱う。

これにより、ケースが表すのは「全入力条件の単純な同時成立」ではなく、優先規則で解決した試合ごとの有効条件に対する条件付き確率となる。条件自体の実現確率は掛けない。

## 例

| 先の条件 | 後の条件 | A対Bなどの共通試合 |
| --- | --- | --- |
| Aが勝利 | Aが40–0で勝利 | Aの40–0へ絞る |
| Aが勝利 | 対戦相手Bが敗北 | 両立、候補は変わらない |
| Aが勝利 | 対戦相手Bが0–40で敗北 | Aの40–0へ絞る |
| Aが勝利 | 対戦相手Bが勝利 | 後のB勝利をその試合だけスキップ |
| Aが40–0で勝利 | Aが敗北 | 後のA敗北をその試合だけスキップ |
| Aの30–10を試合別に固定 | Aが40–0で勝利 | 固定を維持し、その試合での条件をスキップ |

「A全勝 → B全勝」でA対Bが残っている場合、直接対決はA勝利、Bのほかの残り試合はB勝利となる。「B全勝 → A全勝」では直接対決がB勝利となる。

先にA勝利を適用し、次にBの0–40敗北を適用した場合、直接対決の候補はAの40–0だけになる。後からAの40–0勝利が指定されても、追加の確率補正を掛けず、その同じ候補を保持する。

## 入力表記と有効条件の表示

入力した各行は「残り全試合でチームAがB」のまま保持する。一方、実際の適用結果は必ず別に表示する。

- 各条件について適用対象となる未消化試合と、スキップされた試合を確認できる。
- スキップした試合には、対戦カード、節、優先された固定スコアまたは先行条件を示す。
- 例：「Bの勝利条件：A戦を除く残り試合に適用」。同じ相手と複数回対戦する場合は節・試合IDで区別する。
- 対象となる未消化試合がない場合は「対象試合なし」と表示する。
- 対象試合ですべてスキップされた場合は「適用試合なし」と表示する。
- 両立するが候補を追加で絞らない条件は、矛盾・スキップとして扱わない。

一部がスキップされたケースを、例外の説明なく「A全勝かつB全勝」と表示しない。結果JSONにも入力条件と解決後の有効条件・スキップ情報を含める。

## 比較結果

[モンテカルロ仕様](monte-carlo.md)の追加により、計算方式も全比較ケースで統一する。モンテカルロでは同じ試行番号・試合の乱数を共有し、対応のある差とその推定誤差を表示する。同点による範囲と統計的な区間を区別する。

以下は単一確率の比較を記す。詳細モードで上下限が残る場合は、全探索モード仕様の範囲による比較・検算へ置き換える。確率を均等配分した場合の合計1・PO合計3を、上下限にそのまま要求しない。

基準ケースと複数の比較ケースを並べる。各チームについて次を確認できる。

- 各ケースの1〜6位確率。
- 各ケースのPO進出確率。
- 基準ケースからの差。差の単位はパーセントポイント（例：50%→60%は+10ポイント）。
- ケース名、条件の順番、例外を含む適用内容。

各ケースは同一の入力スナップショットに対応付ける。現在状態や共通固定スコアが変わった場合は、以前の結果であることを明示し、新旧の異なる前提の結果を同一の比較として扱わない。未計算・計算中・中止・完了を区別し、部分集計を完成結果として表示しない。

## 検証項目

- 条件のないケースは基準ケースと一致する。
- 単一条件は既存の全勝・全敗・全40–0・全0–40と一致する。
- 優先順位によって直接対決の有効条件が変わる。
- 直接対決でのスキップが、ほかの試合への適用を妨げない。
- 3条件以上で、直前だけでなく全先行条件を維持する。
- 固定スコアは全条件より優先され、基準にも共通で反映される。
- 同じ条件の重複指定で分布が変わらない。
- 勝利→40–0など、両立する後続条件は候補を正しく絞る。
- ホーム・アウェイを反転しても、対象チームから見た意味が一致する。
- 対象試合なし・全条件スキップ・残り試合なしでも結果が定義される。
- ケース間で条件が混ざらず、各ケースのチーム別・順位別合計は1、PO合計は3。
- 表示する差はケースの厳密値と基準の厳密値の差から計算し、表示済み丸め値を引き算しない。

## 既存仕様との差分

既存初版の「単一チーム条件と固定スコアが矛盾したら計算エラー」は、この追加機能では「試合別固定を優先し、その試合でのチーム条件をスキップ」に変更する。未知のチーム、無効なスコア、消化済み試合への固定などの入力不正は、引き続き検証エラーとする。
