# SFL 2026 順位確率ラボ

GitHub Pagesで公開できる、日本語の非公式順位確率計算ツールです。サーバー・APIキー・外部ライブラリは不要です。ポイント・バトル・ラウンドの3段階の順位判定と、厳密全探索／モンテカルロの2方式に対応します。

## できること

「順位確率」と「必要・十分条件の探索」を別の入口で提供します。

- Division S / F の最終1〜6位とPO進出確率を厳密集計。
- 複数の比較ケースに優先順位付き条件（全勝・全敗・全40–0・全0–40）を登録。
- 試合別固定スコアを全ケースで共有し、順位・PO進出確率と基準からの差を比較。
- 固定スコアを最優先し、矛盾する後続条件はその試合だけスキップ。適用内容を計算前と結果画面で確認。
- 詳細モードで未解決同点が残る場合、順位・PO進出確率の上下限と同点確率を表示。完全一致は「追加タイブレーク戦次第」と区別。
- 必要・十分条件の探索で、対象チームのPO進出・1位通過に必要な最低ポイント／勝利数と、保証できるしきい値を厳密探索。
- 境界例・反例と、最終集計値・各試合・プレイヤーマッチ・ラウンドの具体例を表示。
- 厳密探索の組合せ数と、1億・1兆を基準にした規模警告。
- 実結果の登録・訂正・取消、基準順位表の編集。
- ブラウザへの自動保存、設定JSONの入出力、日程などのJSON編集。
- 計算の進捗・経過時間表示と中止。Web Workerで画面をブロックしません。
- モンテカルロの試行回数・シード指定、中止結果の保持、追加試行、再開JSONの入出力。
- 個別の95%区間と、共通乱数による基準差の推定誤差。
- 検算済みの厳密な分数と、計算時の入力を結果JSONへ書き出し。

## モデル

各プレイヤーマッチの勝率は双方50%、独立。最終スコア40–0 / 30–10 / 30–20 / 20–30 / 10–30 / 0–40の重みは1 / 2 / 1 / 1 / 2 / 1です。同ポイントは占有する順位へ均等配分します。バトル差・ラウンド差はデータとして保存しますが、ポイントモードの順位計算には使いません。バトルモードはポイント→バトル差、ラウンドモードはポイント→バトル差→ラウンド差で比較します。バトルモードは各バトル、ラウンドモードは各ラウンドの勝率を50%・独立と仮定します。延長も含め、ポイントと得失点差を同じ試合結果から導出します。3項目完全一致時には、競技細則に従って追加タイブレーク戦で順位を決めます。ユーザーが公式細則を確認した報告を根拠に確定ルールとして扱います（[出典記録](docs/rules-source.md)）。追加戦の勝敗・勝率は生成しません。実力差を考慮した予測ではありません。

厳密全探索を選んだ場合は、全組み合わせの重み付き列挙です。モンテカルロを選んだ場合は同じ条件付き分布から抽選します。自動的に近似へ切り替えることはありません。ポイントモードは小さい整数バッファとBigIntで整数を正確に保持し、同点配分の分母も保持します。詳細モードは試合の同一集計状態を厳密に統合し、BigIntの整数重みで列挙します。全チーム間の順位が変わらないと上下界で証明できる部分木は、その全確率を一括集計します。表示時のみ丸めます。実行時間は端末・ブラウザ・残り試合数に依存し、制限は設けていません。タブを閉じると計算は停止します。

詳細モードでは1試合をバトル36状態、ラウンド426状態に集約します。条件なしの9試合・12試合の詳細全探索は非常に大きくなり、実用時間内に終わる保証はありません。無条件の初期日程全体で詳細モードを完走した性能検証はしていません。近似への自動切替はありません。

比較は基準→各ケースの順に実行し、同じ有効条件の結果はその実行内で再利用します。完了したケースの結果だけを表示します。中止したケースは未完了として残ります。上下限の比較差は保守的な範囲です。

## データの出典と限界

- 基準順位表：ユーザー提供の2026-11-07時点（S第7節・F第6節終了）。[SF6 Freak](https://sf6freak.com/contents/results/sfl-2026/)の両順位表と一致。
- 全60試合の日程とホーム・アウェイ：[格ゲーチェッカー](https://kakuge-checker.com/topic/view/09243/)の各チーム対戦表を参照。各組合せ2試合、各節各チーム1試合、各チームホーム・アウェイ各5試合を検証。
- [公式日程](https://sf.esports.capcom.com/sfl2026/schedule/)は取得時に403となり、直接照合できていません。公式確認済みとして扱わないでください。
- 日程データの試合ID・並び順は本ツール用であり、公式のMatch 1〜3の順番を表しません。
- 基準以前の個別結果は集計値に含まれ、個別結果としては保存していません。過去分を直す場合は基準値を編集します。
- 新しい試合は自動取得しません。実結果の登録か標準JSONの更新で反映します。

## 実行と検証

Node.js 24以降を使用します。依存パッケージのインストールは不要です。

```sh
npm test
npm run build
```

`dist/`が公開用の静的成果物です。ローカルで確認する場合は、任意のHTTPサーバーで`dist/`を配信してください。例：

```sh
python -m http.server 8000 --directory dist
```

`http://localhost:8000/`を開きます。`index.html`のダブルクリック（file://）ではデータ取得・Workerを使用できません。

初期データ全組み合わせの検算は次で実行できます。Division Fでは21億通り以上を列挙するため、完了まで待ってください。

```sh
node scripts/verify-default.js
```

## GitHub Pagesへの公開

1. このプロジェクトのファイル一式をGitHubリポジトリのルートに置きます。
2. リポジトリのSettings → Pages → Build and deployment → Sourceで「GitHub Actions」を選びます。
3. `main`ブランチへpushするか、Actionsの「Publish GitHub Pages」を手動実行します。
4. テスト・静的成果物の生成・Pagesへのデプロイが順に実行されます。

デフォルトブランチが`main`以外なら`.github/workflows/pages.yml`のbranchesを変更してください。相対パスを使用しているため、`https://ユーザー名.github.io/リポジトリ名/`の形式にも対応します。

ソース転送先は https://github.com/tayama0324/sfl-calculator の sfl-handoff-20261109 ブランチです。GitHub Pagesは未公開です。mainのユーザー作成の初期コミットは維持し、.devcontainer設定を引き継ぎます。ソース一式は専用ブランチから取得してください。

## ファイル構成

- `site/`：ページ本体、CSS、JavaScript、標準データ。
- `site/js/model.js`：データ検証、条件適用、現在値の再計算、表示精度。
- `site/js/engine.js`：ポイントモードと探索モードの振り分け。
- `site/js/detailed-engine.js`：得失点差を含む厳密列挙、証明可能な部分木集約、順位・PO上下限。
- `site/js/distributions.js`：プレイヤーマッチ・チームマッチの厳密な同時分布。
- `site/js/comparison-ui.js`：比較ケース編集・適用条件・比較結果の表示。
- `site/js/monte-carlo.js`：試行・チェックポイント検証・再開・反復確認対応の95%区間。
- `site/js/random.js`：シード・試行番号・試合に対応したChaCha20乱数と、偏りを避けた重み付き抽選。
- `site/js/condition-search.js`：成績別の達成可能性・保証の探索、しきい値、反例の再構成。
- `site/js/condition-search-ui.js`：条件探索の設定・結果・具体例。
- `site/js/ranking.js`：順位比較・目標境界の分類。
- `site/js/exhaustive-cost.js`：条件未適用の組合せ数と規模警告。
- `site/js/monte-carlo-ui.js`：推定値・同点による幅・統計的な区間の表示。
- `site/js/worker.js`：計算スレッド。
- `site/data/default.json`：初期順位表と全対戦日程。
- `tests/`：独立した小規模列挙との照合、確率の保存則、条件・入力・更新の検証。
- `docs/specification.md`：仕様。

## 毎節の更新

「残り日程・登録結果」から実結果を登録します。仮定用のスコア選択とは別操作です。バトル差・ラウンド差を空欄にした場合、0ではなく不明として扱います。登録した試合の仮定は削除されます。設定はブラウザ単位で保存されるため、別の端末へ移す場合はJSONを書き出してください。

標準状態を全閲覧者向けに更新する場合は、設定JSONを`site/data/default.json`へ反映して公開し直します。閲覧者の保存済み設定は自動上書きしません。「初期データに戻す」で公開版の標準状態へ戻せます。

## 設定の移行と詳細モードの入力

保存・書き出しはschemaVersion 3です。schemaVersion 1・2と旧ブラウザ保存を読み込み、初版の単一チーム条件を1つの比較ケースへ移行します。移行時の計算方式は厳密全探索、モンテカルロの試行回数は10万です。日程・累計値・登録結果・固定スコアを保持します。標準JSONも旧形式を読み込めます。

バトルモードには全チームの現在のバトル差、ラウンドモードにはラウンド差も必要です。登録した結果の差分が不明なら、個別結果を補完してください。現在の累計だけが判明している場合は、「基準となる集計値を編集」の「入力を現在の累計として再設定する」を選択し、現在値を補完できます。この操作は登録済み結果を基準へ統合するため、以後その過去分の訂正は基準値の編集で行います。

仕様は[シナリオ比較](docs/scenario-comparison.md)と[全探索モード](docs/exhaustive-modes.md)、検証状況は[検証記録](docs/verification.md)を参照してください。

## モンテカルロの使用方法

1. 「計算方式」でモンテカルロを選びます。
2. ポイント／バトル／ラウンドの順位判定を選びます。
3. 試行回数を選ぶか任意指定し、自動生成されたシードを確認します。シードは文字列で指定でき、同じ入力・シード・各種バージョン・総試行数で結果を再現します。
4. 計算を開始します。比較ケースは同じ試行番号・試合の乱数を共有します。
5. 中止した場合は全ケースの処理が揃った試行まで保持します。「指定回数を追加試行」で続けられます。追加する回数を入力すると、完了数に加算されます。

中止・完了時にチェックポイントをブラウザへ保存し、次回表示時に復元します。「結果JSON」は再開可能なチェックポイントを書き出します。通常の「JSONを読み込む」から復元でき、そのディビジョンの入力も一緒に復元します。設定JSONだけでは試行結果は復元できません。入力・条件・シード・順位判定が変わると追加試行はできず、新規計算になります。試行回数だけの変更は追加可能です。保存容量不足でも集計は画面に残るため、JSONを書き出してください。

確率は推定値です。「観測なし／N試行」は確定0%を意味せず、全試行での観測も確定100%を意味しません。詳細判定の未解決同点による上下限と、有限試行の統計的な区間は別に表示します。95%区間はHoeffding不等式と各試行数への誤差確率配分による保守的な区間で、途中確認や任意の中止・追加試行にも対応します。各指標・各端点ごとに個別の保証であり、全チーム・全ケースの同時保証ではありません。

基準との差は同じ試行番号の寄与を引き算して集計します。個別ケースを独立と仮定した誤差合算はしません。同点で幅がある場合は差の下限・上限にも別々の区間を表示します。

再現性のため、乱数生成器・条件付き分布の並び順・区間方式のバージョンをチェックポイントに保存します。互換性がないデータは再開しません。乱数のキー生成にWeb Cryptoを使用するため、HTTPSまたはlocalhostで開いてください。

両ディビジョンの初期日程・3段階の順位判定・各3ケースを10万試行ずつ検証するには以下を実行します。測定値はNode.jsでの値であり、ブラウザの実行時間を保証しません。

```sh
node scripts/verify-monte-carlo.js
```

詳細は[モンテカルロ仕様](docs/monte-carlo.md)を参照してください。

## 必要・十分条件の探索

1. 上部の「必要・十分条件の探索」へ切り替えます。
2. 対象チーム、PO進出／1位通過、順位判定を指定します。ラウンドまでが標準です。
3. 通常状態（仮定なし）か、既存のシナリオケースを選びます。通常状態は確率画面で指定した固定スコアも無視します。
4. 「必要・十分条件を探索」で厳密探索を実行します。

結果は残りの獲得ポイントとチームマッチ勝利数の単独条件です。「以上」の全実現可能パターンを調べます。必要条件を満たすだけでは達成を保証しません。十分条件のしきい値以上では、全パターンで目標を保証します。前提により実現しない成績の間にしきい値が位置する場合もあります。既に確定・達成不可能・その指標だけでは保証不可を区別します。

完全一致で目標の境界をまたぐ場合は、達成可能性に含めますが保証には含めません。例えば3〜4位が完全一致ならPOは追加戦次第。1〜3位の3チームが完全一致ならPOは全員確定し、1位は追加戦次第です。追加戦の実施はユーザーによる公式競技細則の確認に基づく確定ルールです。その勝敗を50%で抽選したり、同点を均等配分したりしません。

「境界例」「保証できない例」から、最終順位表と残り試合の具体的なスコアを確認できます。詳細モードでは、得失点差を実現する各プレイヤーマッチのバトルスコア、ラウンドモードでは各バトルのラウンドスコアも表示します。未確定の例は敗退確定の反例と区別します。

順位が確定した部分木でも、残りポイント・勝利数の実現可能性を厳密に保持して集約します。未完了・中止からは確定条件を表示しません。結果JSONは自己完結した代表例カタログと入力を保存します。条件探索結果のページへの再読み込み・途中再開は今回の範囲外です。設定はschemaVersion 3の任意フィールドconditionSearchとして保持し、旧設定を読み込むと初期値を補います。この設定は確率計算のシードや再開条件に影響しません。

厳密全探索と条件探索には、条件を無視した組合せ数（6^残試合数／36^残試合数／426^残試合数）を表示します。確率計算は基準を含むケース数を掛けた参考上限も表示します。1億以上で注意、1兆以上で強い警告を出しますが、禁止や追加確認、自動切替はしません。実際の処理量は条件や部分木集約で減る場合があり、所要時間の上限ではありません。

詳細な条件探索は依然として非常に大規模になり得ます。初期日程全体のラウンドまでの条件探索が実用時間内に完了することは保証しません。仕様と検証記録はdocs/condition-search.mdおよびdocs/verification.mdを参照してください。
