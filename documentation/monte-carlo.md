# モンテカルロ：合意済み追加仕様

## 状態と選択項目

推奨案に対するユーザーの承認に基づく追加仕様。v0.3.0で実装済み。既存の厳密計算は維持する。

| 設定 | 選択肢・初期値 |
| --- | --- |
| 計算方式 | 厳密全探索／モンテカルロ。既存設定の初期値は厳密全探索 |
| 順位判定 | ポイントのみ／バトルまで／ラウンドまで |
| 試行回数 | 1万・10万・100万・任意の正の整数。初期値10万 |
| 乱数シード | 自動生成し表示。手動指定・保存・再利用も可能 |
| 終了 | 指定試行数に到達、またはユーザーが中止 |
| 継続 | 途中結果を保持し、同じ入力・シードで追加試行 |

厳密計算から近似へ自動切替しない。画面の「全探索」という表記は計算方式に用い、モンテカルロ選択中の順位判定は「ラウンドまで」等と表示する。

## 1試行の定義と生成モデル

1試行は、あるディビジョンの残り全試合を生成して最終順位を集計すること。基準と全比較ケースについて同じ試行番号の試行を行う。ディビジョンごとの計算は独立する。

- 厳密計算と同じポイント・バトル・ラウンドの同時分布を使う。
- シナリオの優先順位、共通の固定スコア、試合ごとのスキップを先に解決する。
- 解決した条件下の試合分布から直接抽選する。条件を満たすまでリーグ全体を引き直す方法にはしない。
- ポイントモードでは、同点が占有する順位へ各試行の寄与を均等配分する。試行ごとに架空のタイブレーク勝者を抽選しない。
- 詳細モードでは厳密計算と同じ定義の順位・PO下限と上限、未解決同点、PO境界の同点を集計する。
- ラウンドまで判定した場合の完全一致は「追加タイブレーク戦次第」と区別する。追加戦の実施は確定ルールとして扱うが、その勝敗は探索対象外とし、勝率50%や均等配分による勝者の抽選は追加しない。未探索の得失点差による同点とは理由を分ける。
- 不明な現在の得失点差を0で補完しない。順位判定に必要な値の検証も既存と共通。

## シナリオ比較と乱数共有

各試行番号・各試合に対応する共通の乱数を、基準と全ケースで共有する。条件によって抽選対象の分布が変わっても、各ケースの周辺分布は正しい条件付き分布を保つ。同じ有効条件なら同じ抽選結果となる。

同じ試合の乱数から各ケースの条件付き累積分布を使って抽選するなど、対応関係を固定する。条件付き分布の状態順序もバージョン管理する。乱数共有で差の分散が必ず小さくなるとは保証しない。

ケースや試合の処理順序、Workerのバッチサイズ、途中の表示回数で対応がずれないようにする。試合ごとの乱数ブロックを分離し、可変回数の乱数取得が別の試合・試行へ影響しない構造にする。整数重みからの抽選で単純な剰余等による偏りを導入しない。

## 再現性と追加試行

同じ入力、シード、モデル・乱数生成器・抽選手順のバージョン、総試行回数なら同じ集計値を再現する。Math.randomだけに依存しない。シードは入力文字列として保存し、数値変換で桁を失わない。

「新しく計算」は試行番号0から開始する。「追加試行」は完了済みの次の試行番号から実行する。追加数を指定し、完了済み＋追加分の総数を表示する。たとえば最初の10万回＋追加10万回は、同じシードで最初から20万回の集計と一致する。

現在値、日程、共通固定スコア、比較ケースの内容・順序、順位判定、シード、モデル等が変更された場合、既存集計へ追加できない。新規計算として扱う。試行回数の追加指定と表示桁数の変更は再計算を要求しない。

## 中止と途中結果

Web Workerでバッチ処理し、イベントを受け取れるよう定期的に制御を返す。経過時間、完了試行数、予定数、進捗を表示する。

1試行番号について基準と全ケースの処理が完了してから、その試行を集計へ確定する。中止時は全ケースに共通する完了試行までを保持し、途中の試行を含めない。全ケースの完了数を揃え、ケース間の対応を保つ。中止はWorkerの応答を待って集計を受け取り、その後に停止する。

途中表示も「モンテカルロ推定・N試行時点」と明示する。N=0では確率・誤差を表示しない。Workerの異常停止では、最後に受領済みの整合するチェックポイントだけを復元対象にする。

## 推定値と2種類の不確かさ

画面・結果JSONでは、次を別々に保持・表示する。

1. 同点による範囲：未知のタイブレーク等により、同点グループ内の順序を確定できない幅。
2. 統計的な誤差：有限回の試行から確率を推定するための幅。

ポイントモードの各順位・POは各試行の寄与の平均。詳細モードは各試行の下限寄与と上限寄与を別々に平均し、下限推定値〜上限推定値を表示する。その各端点に個別の95%信頼区間を付ける。

PO進出確率と基準からの差は比較表で確認できるようにし、順位別の区間は詳細表示にまとめてもよい。すべての区間を一つの「確率範囲」に混ぜない。これらは大会モデルの妥当性やチーム実力の不確実性を表す区間ではない。

## 95%区間の計算方針

同点配分では各試行の寄与が0/1に限らず1/3などになる。一般の[0,1]の寄与を扱える方法を用い、二項分布専用の式をそのまま使用しない。

途中確認・任意の中止・追加試行にも対応するため、初版ではHoeffding不等式と誤差確率の配分による、保守的な反復確認対応の区間を使用する。α=0.05、N≥1とし、各Nにα_N=α/[N(N+1)]を割り当てる。各指標について全Nの誤差確率の合計がα以下となる。

- [0,1]の試行寄与：平均±sqrt(log(2/α_N)/(2N))を[0,1]に切り詰める。
- [-1,1]の試行寄与：平均±2×sqrt(log(2/α_N)/(2N))を[-1,1]に切り詰める。

各指標・各端点について個別に適用する。すべてのチーム・順位・ケース・上下両端を同時に95%保証する区間ではないと説明する。通常の固定回数だけで評価する区間より広くなり得る。区間の計算方法とバージョンも保存する。

## 基準との差とその誤差

共通乱数で対応付けた同じ試行番号の寄与を引き算し、その差を集計する。別々に求めた確率の標準誤差を、独立と仮定して合算しない。

- 単一確率：ケース寄与−基準寄与の平均と、その個別95%区間。
- 詳細モードの保守的な差の下限：ケース下限寄与−基準上限寄与。
- 同じ差の上限：ケース上限寄与−基準下限寄与。

差の単位はパーセントポイント。各試行の差は[-1,1]として扱う。詳細モードでは「同点による差の範囲」と「各端点の統計的な区間」を分ける。

## 未観測と全試行での観測

- 寄与の合計が0の場合は「観測なし／N試行」と表示し、確定0%と区別する。95%区間の上端も確認できる。
- 寄与が全試行で1でも、有限試行だけから確定100%とは表示しない。
- 同点による分数寄与には「発生件数」ではなく、寄与率と必要に応じて有効寄与合計を表示する。
- 微小な正の推定値は表示時の丸めで0%に消さない。観測されない稀な事象の確認には厳密計算を案内する。

## 保存・復元

設定には計算方式、順位判定、シード、試行回数を保存する。途中・完了結果は入力スナップショット、各種バージョン、完了試行数、次の試行番号または同等の乱数状態、再開に必要な集計値、対応する基準差の集計を含める。

チェックポイントのJSON書き出し・読み込みに対応し、ページを開き直して同じ条件で追加試行できるようにする。設定だけのJSONと、再開可能な結果JSONを区別する。互換性のないバージョン、入力不一致、不正な集計は再開せず理由を表示する。

全試行の生データを保持する必要はない。同点配分の寄与を60倍の整数で加算するなど、カウントと対応する差の集計を正確に保持する。ブラウザ保存の容量超過を、計算失敗や試行数の変更と混同しない。

## 検算・受け入れ条件

- ポイントモードでは各試行・全集計で、チーム別順位合計1、順位別6チーム合計1、PO合計3。
- 詳細モードでは厳密モードと同じ上下限の整合性を試行集計に対して確認する。95%区間の端同士には合計1・3を要求しない。
- 試行数・各指標の平均・区間の範囲が整合し、N=0や未観測でNaNや確定0%を出さない。
- シード固定時の再現、バッチサイズ・中止位置に依存しない継続、分割追加と一括計算の一致を確認する。
- 全ケースの試行数が揃い、同じ有効条件なら抽選結果と集計値が一致する。
- 条件付き分布の重み、優先規則、延長、差分の符号、ホーム／アウェイの意味が既存モデルと一致する。
- 小規模に厳密計算できる入力と照合する。信頼区間は確率的な性質を持つため、単一の乱数実行が区間に入ることだけを必須テストにしない。
- 区間式の境界・被覆率の理論的根拠を検証し、単一確率・詳細モードの各端点・対応差を取り違えない。
- チェックポイントの復元で値が一致し、不正・不一致なデータを現在の有効な集計へ混ぜない。
