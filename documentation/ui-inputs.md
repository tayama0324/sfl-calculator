# v0.5.0：入力と結果の整理

2026-11-09の追加仕様。以前のシナリオ比較・条件探索画面に関する記述と異なる場合、この仕様を優先する。

## 画面の流れ

現在のチーム状況 → 残り日程 → 計算方式・順位判定（または条件探索の設定）→ 結果。
結果は緑系の背景・枠で入力と区別する。残り日程は節ごとに折りたたみ、最初の節を開く。
順位確率の概要は1位通過とPO進出を並べ、1〜6位の内訳・適用条件は詳細へまとめる。

シナリオ比較の編集UIを隠す。画面から実行する計算では比較ケースを適用せず、試合ごとの仮定だけを適用した基準を計算する。保存済みのケース定義・比較エンジン・従来形式のJSONは維持する。旧比較チェックポイントと新しい単独計算の条件が一致しない場合は追加試行せず、新規計算が必要となる。通常の新しい単独計算は保存・復元・追加試行できる。

## 試合の入力

- スコアの直接選択：将来の仮定。未指定なら全スコアを探索する。
- 「詳細を入力」：スコア、ホーム側のバトル得失点差、ラウンド得失点差を入力する。
- 入力の種類は「将来の仮定」が標準。「確定した結果」に切り替えた場合だけ現在の累計へ加算する。
- 将来の仮定は未消化試合のままとし、現在の累計には加算しない。条件探索の「残り獲得ポイント・勝利数」には、その仮定した試合分も含める。
- 仮定の差分の空欄は未指定で、成立する値すべてを探索。確定結果の空欄は不明で、必要な差分が不明なら詳細順位計算を開始しない。
- ホーム側の差分は獲得数−失った数。アウェイ側には符号反転して反映する。
- スコア・バトル差・ラウンド差は同一の試合結果として成立する組合せだけ受け付ける。スコアのみの変更が保存済みの差分と矛盾する場合、既存入力を保持し理由を表示する。
- 仮定と確定結果は同じ試合に重複して保持しない。種類を切り替えると元の種類から移動し、二重計上しない。

設定schemaVersion 3の各divisionへ任意フィールド `fixedDetails` を追加した。
`fixedScores[matchId]` のスコアがある場合だけ、次の形式を保持できる。

```json
{
  "fixedScores": {"s-8-fav-ixa": "40-0"},
  "fixedDetails": {"s-8-fav-ixa": {"battleDiff": 7, "roundDiff": 14}}
}
```

差分は整数またはnull。従来の `fixedScores` の文字列形式は変えていない。
指定した差分で同時分布を絞り、重みを保った条件付き分布として計算する。
ラウンド差を指定してバトル順位で探索する場合も、ラウンド分布で条件付けてからバトルへ周辺化する。
ポイント順位では固定スコアからポイントが確定する。差分未指定なら従来の抽選順序と重みを変えない。
差分変更はモンテカルロの再開識別情報にも含まれ、不一致の集計へ追加できない。

## 1位・PO進出の同時条件探索

画面からは対象チーム・順位判定だけを指定する。目標・シナリオ前提の選択をなくし、入力済みの試合仮定を適用する。
新しい内部設定は `goal: "both"`、`caseId: "@input"`。
旧APIの `po` / `first`、仮定を無視する `@normal`、ケース指定も維持する。

試合パターンの探索木は一度だけ走査し、各終状態を1位（境界1）とPO（境界3）の両方へ分類する。
部分木は両方の目標の分類が証明できた場合のみ集約し、残りポイント×勝利数の実現可能な組を保持する。
同点・必要条件・十分条件の定義は従来と同じ。目標ごとのセル・代表例・しきい値は別に集計する。
単独目標より枝刈りが弱まる場合があるため、所要時間が必ず短くなるとは保証しない。

結果JSONの新形式は `kind: "sfl-condition-search-results"`、`goal: "both"`。
`results.first` と `results.po` に従来の単独結果形式を格納する。
未完了の探索からは、どちらの目標についても必要・十分条件を確定表示しない。
条件探索結果JSONの画面への再読込・途中再開は引き続き対象外。

## 条件表示の文言調整

条件探索の画面では勝利数の条件・境界例の選択を表示せず、ポイントの条件だけを表示する。エンジンと結果JSONの勝利数集計は維持する。必要条件は「あとN点以上必須」、正の最低点がない場合は「-」。十分条件は「あとN点で確定」、点数だけで保証できない場合は「他力または得失次第」。達成不可能はそのまま明示し、既に達成保証されている場合は「あと0点で確定」とする。

「他力または得失次第」は原因の分類結果ではない。他チームの結果・得失点差・追加戦の影響は重なり得るため、個別表示には対象チームの成績を固定した場合などの追加集計と判定基準が必要。現在の成功・失敗・未確定の存在だけで原因を断定しない。

## 3目標と基準表示の整理

条件探索は `goal: "all"` で1位・2位以内・PO進出を同時に集計する。
単独の2位以内は `second`、境界順位2。結果JSONの `results.second` に保存する。
旧 `both` は従来どおり1位・POの2目標を維持する。
結果の計算時入力に残り日程の仮定がある場合のみ「残り日程の仮定を適用」を強調表示する。
入力変更後は、既存結果のバッジも計算時入力に対応し、「変更前の入力による結果」を併記する。
再計算後は新しい入力の仮定有無に従う。

基準に含まれる過去の試合は「現在のチーム状況」に移し、「基準となる集計値を編集」のUIとそのイベント処理を削除した。
設定JSONの保存・読込は維持する。
マッチ単位の必要・十分条件はv0.6.0で実装済み。[仕様](match-conditions-proposal.md)を参照。


## v0.7.0 得失込みの十分条件

詳細モードでは獲得ポイントの十分条件に、探索済みの得失増分を含める。
ポイント、バトル得失、ラウンド得失の順に辞書式で比較し、各成分の同時下限ではない。
境界は保証できない最大成績の最後の整数成分+1。境界そのものは実現できなくてもよいが、
境界以上の成績が実現可能な場合のみ表示する。
ラウンド探索は「X点（得失B/R）以上」または「他力」。バトル探索は
「X点（バトル得失B）以上」または「他力またはラウンド得失次第」。
保証済み・不可能は専用表示を維持する。「他力」には追加タイブレーク戦を含める。
ポイントのみの探索は従来表示を維持する。マッチ条件は点数のみを指定する。
両指標を共通の必要／十分条件の列に表示し、モバイルでは両指標とも縦配置にする。


## v0.8.0 全チームの単独条件

マッチの十分条件内に「全チームの単独条件」を追加した。
他チーム同士を含む残り全試合・両チームについて「X点以上」「X点以下」を抽出する。
各条件は単独で保証し、いずれか1つを満たせばよい。40点以上と0点以下は「40点」「0点」。
条件がない場合は「この形式では十分条件なし」と表示し、他力の必要性は断定しない。
その下に既存の「自チームの組み合わせ条件」を保持する。必要条件は自チームの試合が対象。
候補の展開、成立例、10点緩めた反例は目標ごとに表示する。


## v0.9.0 全チームのマッチ必要条件

必要条件も全チーム・全残り試合に拡張した。達成確定＋未確定ケースでの各試合の最低点を
「すべて必須」として「かつ」で表示する。0点は省略し、正の最低点がなければ「-」。
達成不可能は専用表示。仮定で既に満たされる条件も含む。
各条件から最低点の境界例へ移動できる。4条件以上は残りを展開する。


## v0.10.0 条件表示・仮定への反映

十分条件は「自力での確定条件」→「他力での確定条件」。他力の候補が空なら、そのセクションと
自力見出しを省略する。マッチ必要条件は全件表示し、節ごとの境界例ボタンは表示しない。
同じ試合の両側下限の合計が40以上で、許されるスコアが一意のときだけ「結果がX - Y」に縮約。
合計40だけでは一意と限らないため、20以上＋20以上などは「かつ」のまま。

ポイント探索の必要条件下に「この条件でバトル得失点差を探索する」を表示する。
押すと条件を試合ごとにまとめ、入力時の仮定と両側の下限に一致するスコアを残り日程へ反映し、
battlesモードに切り替える。30点条件は可能なら30–20。複数の許容結果のうち一例を選ぶ操作であり、
必要条件全体の確率を再計算する操作でも達成を保証する操作でもない。実行は探索ボタンから行う。
不可能な目標にはボタンなし。古い結果は無効化し、入力のfingerprintも照合して誤適用を防ぐ。


## v0.10.1：任意の仮定選択を撤廃

v0.10.0の30–20優先と、下限だけから独立にスコアを選ぶ処理を撤廃した。
下限を満たしても達成可能なケースの組み合わせとは限らないため。
達成確定・未確定ケースの各試合両側の最低点に加え最高点も保持し、その範囲で
スコアが一意なら結果表記に縮約する。合計点による縮約制限は不要。
ボタンではその一意スコアだけを固定する。複数結果が残る試合は固定せず、
次のバトル探索で達成可能なケースを除外しない。既存の仮定は維持する。
結果version 6では `possible.max` に最高点と代表例を追加。旧version 5は最低点だけで検証する。
旧ボタンが残した誤った仮定は、解除後にポイント探索から再実行する必要がある。


## v0.11.0 仮定適用の強調

仮定ありの計算時snapshotを持つ結果は全体をオレンジ系にし、先頭に適用した仮定の件数・試合・
スコア・得失を表示する。最初の1件は常時表示、残りは展開できる。条件探索・順位確率に共通。
必要条件の指定済みスコア由来の節には「入力済みの仮定」ラベル。
必要条件には「入力した仮定が成立する場合の必要条件です。仮定で既に指定した結果も含まれます。」、
十分条件には「入力した仮定が成立する場合に限り、達成を保証します。」を表示する。
「仮定を解除して再探索」は現在の入力のスコア・得失仮定をすべて外して再計算する。
結果の仮定はsnapshotから表示し、入力のみを変更しても古い結果の警告は解除しない。


## v0.11.1 具体例の表示

折りたたみは「具体例を見る」。初期表示は最初の有効な例ボタンと一致し、確定条件の成立例を最優先。
次に必要条件ギリギリの達成例、必要条件を満たす未達成・得失次第の例を表示する。
該当例がないボタンは省略。必要点ギリギリでも未確定なら「達成の可能性が残る例」と明示し、
必要条件を満たさない反例を「満たした」とは表記しない。ラウンド探索の同点は追加戦次第。
ヘッダーには押したボタン名と、例ID・残り獲得点を表示。仮定ありの具体例は周囲と同じオレンジ系。


## v0.12.0 仮定入力と残り日程の統合

詳細入力の種類選択を削除し、常に将来の仮定として保存する。現在の累計や確定結果は変更しない。
保存済みresultsは引き続き集計し、残り日程から除外する。
残り日程は現在のチーム状況の下部に閉じたdetailsとして統合し、試合数と仮定件数をsummaryへ表示。
初期表示で最初に見えるselect等のフォームは計算設定。操作中は開閉状態を維持する。
AND条件入力の拡張は[仕様検討](and-match-assumptions-proposal.md)を参照（未実装）。
